# AI 技术工作区规则

`for_ai` 是项目本体所在位置。源代码、测试、配置、脚本、技术文档和验证证据默认都放在这里。

## 接手项目

1. 先读取 `../AGENTS.md` 与 `../for_human/PROJECT.md`。
2. 检查当前实际代码、配置、测试与运行状态，不根据过期摘要猜测。
3. 区分已经确认的事实、待验证假设和用户偏好。
4. 在实施前确定最小充分方案，避免在最小闭环尚未验证前过度工程化。

## 技术责任

- AI 是技术方案、实现方式、安全底线、必要测试和专业验收的主要负责人。
- 对纯技术问题，应先检查项目、查阅对应版本的官方资料或做最小实验，再自行选择并记录依据。
- 不要求非技术用户替 AI 选择框架、库、数据格式、目录拆分或测试工具。
- 若多个方案在用户可感知的体验、成本、稳定性、维护负担或风险上存在明显差异，将差异翻译成大白话，给出推荐后再询问用户。

## 推荐的内部结构

按项目真实需要创建，不要为了形式生成空目录：

```text
for_ai/
├── src/       # 项目源代码
├── tests/     # 自动化测试
├── docs/      # AI/开发者需要的技术资料
├── scripts/   # 构建、维护和验证脚本
└── evidence/  # 有保留价值的验证证据
```

## 实施与验证

- 优先完成可运行、可验证的最小闭环，再逐步增加必要能力。
- 修改后运行与变化相匹配的测试；不能运行的测试必须说明原因和风险。
- 测试必须验证用户目标和关键失败路径，不能只验证代码能够导入或页面能够打开。
- 不得把模拟结果描述成真实环境已经通过。
- 不得在没有证据时宣布完成。

## 同步人类协作面板

每次产生实质进展、失败、阻塞、范围变化或重要决定后，更新 `../for_human/PROJECT.md`：

- 用大白话说明结果和用户影响；
- 写明哪些内容已经实际验证；
- 保留尚未完成或尚未确认的事项；
- 需要用户决定时，说明背景、主要影响和 AI 的建议；
- 不把长日志、代码或敏感信息复制到人类文档中。
