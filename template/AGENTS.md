# Human-AI Workspace 项目协作规则

本项目分为：`for_human`（人类协作信息）和 `for_ai`（项目实现与技术工作）。

## 接手顺序

先读取：

1. `for_human/PROJECT.md`：目标、场景、范围和用户完成标准；
2. `for_human/STATUS.md`：当前状态与验证结果；
3. `for_human/DECISIONS.md`：待决定和已确认事项；
4. `for_ai/AGENTS.md`；
5. `for_ai` 中与当前任务有关的实际代码、配置、测试和资料。

以实际代码、配置和验证结果为事实，不要只根据聊天记录或摘要判断状态。

## 文件职责

- `PROJECT.md`：相对稳定的目标、使用场景、期望结果、用户层完成标准和范围。
- `STATUS.md`：当前能做什么、完成/验证到什么程度、未完成、阻塞和下一步。
- `DECISIONS.md`：影响用户体验、成本、维护、依赖、风险、权限或不可逆操作的待决定事项与已确认决定。
- `for_ai`：源代码、测试、配置、技术资料和验证证据。

同一信息只保留一个主要来源；历史技术过程放在 Git 记录或 `for_ai`，不要写成 `STATUS.md` 流水账。

## 人类可读内容

`for_human` 必须使用大白话，明确区分已完成并验证、已完成但待验证、未完成、阻塞和已废弃；说明对用户的实际影响；不得写入密钥、令牌、隐私数据、长日志或大段代码。

## 决策分工

- 纯技术问题由 AI 通过检查代码、查官方资料、测试或专业判断自行比较并选择；不要把未经解释的技术名词交给用户选择。
- 若选择会影响体验、成本、维护、外部依赖、安全、权限、生产环境或不可逆操作，用大白话说明后果和 AI 建议，写入 `DECISIONS.md` 并询问用户。
- 主动发现用户没想到的重要问题；每次只问一个可能实质改变方案的高信息增益问题。
- 用户授权 AI 自行选择后，记录依据并继续推进，不要反复询问同类技术细节。

## Git

- 工作区根目录已由 CLI 初始化为 `main` 分支，并包含初始模板提交。
- `for_human` 任意层级只跟踪 Markdown；其他位置默认可跟踪。项目产生明确不需版本控制的依赖、缓存或构建产物时，按实际技术栈补充根目录 `.gitignore`，不要取消 `for_human` 的既有规则。

## 完成与同步

- AI 负责专业验收标准和必要测试；用户负责最终使用体验验收。
- 没有可复核证据，不得把“计划完成”或“代码已写”说成“功能完成”。
- 目标/场景/范围变化时更新 `PROJECT.md`；进度、失败、阻塞或验证变化时更新 `STATUS.md`；重要用户决定变化时更新 `DECISIONS.md`。
- 人类文档与实际实现冲突时，立即以实际证据纠正文档。
